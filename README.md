# 場景單字輸入練習

依照「生活場景」分類，逐字敲出英文的練習 App。
互動架構參考 [wordmomo](https://joshua19683721.github.io/wordmomo/)，
內容全部取自《英語單字口袋書（1–6級）》PDF，共 **889 條**。

---

## 快速開始

```bat
start.bat
```

會開啟瀏覽器並連到 `http://127.0.0.1:8848/`。
關掉那個 DOS 視窗就會停止伺服器。

不想開伺服器也可以直接雙擊 `index.html`（`file://` 下同樣可用，
只是網址深層連結會失效）。

## 練習方式

每一個單元都是 **單字 → 詞組 → 整句** 的循序漸進結構，
每一步的內容都出自 PDF 同一條目：

| 步驟 | 類型 | 內容來源 | 中文從哪來 |
|---|---|---|---|
| 1 | 單字 | 目標單字 | PDF 釋義 |
| 2 | 單字 | 同一句例句裡的另一個字 | PDF 釋義 |
| 3 | 詞組 | 固定搭配（優先用例句裡真的出現的） | 人工對照表 |
| 4 | 整句 | PDF 的完整例句 | PDF 原書翻譯 |

以「飲食餐桌 › 單元 1」為例：

```
1. 單字   lunch                      /lʌntʃ/          午餐
2. 單字   go                         /ɡoʊ/            去
3. 詞組   a big lunch                /ə bɪɡ lʌntʃ/    一頓大午餐
4. 整句   Let's go get some lunch.   /lɛts ɡoʊ ɡɛt sʌm lʌntʃ/   我們去吃午餐吧
```

> **為什麼詞組不用「把兩個字的釋義串起來」？**
> 早期版本會這樣做，結果生出「書厚的」「應該答案」「電影電影院」這類讀不通的中文。
> 對正在學英文的人來說，錯誤的中文比沒有中文更糟。
> 所以現在詞組只從人工對照表取（1400+ 筆），沒對應到的單元就改用
> 「同一句裡的另一個單字」補位——寧可少一層，也不要給錯的譯文。
>
> **目前 889 / 889（100%）** 個單元都有詞組步驟。
> 後補的那 110 筆（純功能詞、例句極短的那批）一律**取自該單元自己的例句**，
> 所以學到的是自己正在讀、正在打的那一句裡真正會出現的語塊，
> 而不是憑空配出來的搭配。這 110 筆被釘在 `tools/phrase_expected.json`，
> `npm run build` 會逐筆比對英文與中文，任何一筆被其他片語蓋掉就讓建置失敗。
> 每次 `npm run build` 也會把缺口寫進 `tools/need_phrase.txt`，正常情況是 0。

### 快捷鍵

| 按鍵 | 功能 |
|---|---|
| `Space` | 這句完成後 → 下一步；沒完成 → 重讀目前這個字 |
| `Enter` | 重打目前這一步 |
| `Alt` + `Z` | 開／關解析面板 |
| `Alt` + `'` | 朗讀這一句 |
| `Alt` + `H` | 看答案 |
| `Alt` + `B` | 隱藏／顯示中文提示（自我測驗用） |
| `Alt` + `N` / `P` | 下一個／上一個單元 |
| `←` / `→` | 同上 |
| `Esc` | 關閉面板 |

同一個字**打錯 3 次**會自動浮出字樣並朗讀（次數可在右上角調整），
同時進「📕 錯字本」。

### 關於撇號（`'`）

PDF 用的是排版撇號 `’`（U+2019），但一般鍵盤按 Shift+2 得到的是 `'`（U+0027），
學生永遠打不出來，會被 App 判成錯字。所以：

- **題庫產生時**把英文裡打不出來的字元換成半形（`’`→`'`、`“”`→`"`、破折號→`-`），
  本次共修正 **142 處**
- **App 也把兩種撇號視為等價**，不管你打 `'` 還是 `’`、或從文件貼上文字進來，都算對
- 輸入框永遠顯示「打得出來」那一種

> 只套用在英文字段；IPA（`ˈ ː ɡ ʌ ɹ ʃ` 等）與中文完全不受影響。

### 中文用字：全部繁體，並維持台灣寫法

`npm run build` 最後一步會跑 `tools/audit_simplified.py`，題庫一旦出現簡體字就讓建置失敗。
檢查刻意**不用** OpenCC 的 `s2t` 整句轉換——它連「異體字／地區用詞」也會動，
會把本來就正確的台灣繁體字改掉，例如：

- 「台灣」被換成「臺灣」（台灣習慣用「台」）
- 「吃東西」被換成「喫東西」（「喫」是古字）
- 「游泳」被換成「遊泳」（語意變成「到處玩」）
- 「皇后」被換成「皇后後」（直接改錯了意思）

所以只認 OpenCC 的 `STCharacters.txt`（純「簡→繁」單字對照，3741 組），
外加人工排除清單。掃描結果是全專案**原本就已是繁體**，
只有 3 個漏網的簡體字，而且都是我寫程式時打錯的：

| 位置 | 修正 |
|---|---|
| `app.js` 註解 | 中文出題 |
| 詞組對照表「一頓大午餐」 | 一頓大午餐 |
| 詞組對照表「前幾天」 | 前幾天 |

> 過程中踩到兩個坑，都記在 `tools/audit_simplified.py` 的註解裡：
> 一是用字串 `set(...)` 定義「可疑簡體字」時，不小心打進去的是**繁體**的
> `園`(U+5712)、`圖`(U+5716)，把正確的「公園」「花園」全數誤報成簡體；
> 現在改成用碼位明確定義（簡體那個字是 U+56ED，繁體是 U+5712，差一點點）。
> 二是本文件原本在說明表格裡直接擺出簡體字當例子，結果自己被檢查器抓到；
> 現在一律改用碼位描述，不在文件裡放簡體字，檢查就不需要任何例外清單。

### 其他功能

- **🔍 查單字**：889 個單字全部可查。英文、中文、音標、例句都能搜尋，
  命中處會反白；點任一列直接跳到該單字所屬的場景開始練習。
  網址也能直接開：`#browse/lunch`、`#查單字/午餐`
- **等級篩選**：首頁可只看 1–6 級其中一級
- **進度自動儲存**：存在瀏覽器 localStorage，重開自動接續
- **📕 錯字本**：依出錯次數排序。顯示的是**實際打錯的那個字**自己的中文與音標
  （不是它所在單元的目標字）；點任一列會跳到「真的會出現這個字」的那一步，
  並清掉舊答案，讓你真的重打一次
- **📊 學習統計**：各場景完成度條
- **深層連結**：`index.html#food/12/3` 可直接開到某個場景的第 13 個單元第 4 步；
  網址會隨著你的操作自動更新

## 音標是怎麼來的

PDF 本身沒有音標。本機連不到 `dictionaryapi.dev`，
但 GitHub raw 連得到，所以改用 **CMUdict（ARPAbet）離線換算成 IPA**：

```
lunch   L AH1 N CH      →   /ˈlʌntʃ/
student S T UW1 D AH0 N T →  /ˈstuːdənt/
book    B UH1 K         →   /ˈbʊk/
```

換算規則：主要重音 → `ˈ`、次要重音 → `ˌ`、`AH0` → `ə`、`ER0` → `ɚ`、
長母音補 `ː`（`iː uː ɑː ɜː`）。**重音標記放在音節開頭**
（音節的起始輔音之前），和教科書寫法一致，而不是 CMUdict 原始的「標在母音前」。

覆蓋率：

- 889 個單字 **全部**有音標
- 3153 個練習步驟 **全部**有音標（整句會逐詞拼起來，人名查不到就略過）

## 內容是怎麼做出來的

整條 pipeline 可以重跑：

```bash
npm run build     # 解析 → 套校正 → 檢查 → 產生題庫
npm test          # 88 項自動測試
```

```
source.pdf
   │  tools/parse_pdf.py        PDF → 889 條結構化條目
   │                            （軟連字符編號、引號、單複數同欄…）
   ▼
tools/lexicon.json
   │  tools/apply_fixes.py      套用人工校正（tools/fixes.json）
   │  tools/check_lexicon.py    結構檢查
   │  tools/need_phrase.txt     列出哪些單元還缺詞組步驟
   ▼
   │  tools/fetch_ipa.py        CMUdict → IPA（tools/ipa.json）
   │  tools/scenarios.py        21 個生活場景的分類表
   │  tools/build_bank.py       組裝成 889 個練習單元、3153 個步驟
   ▼
data/banks.js  →  前端載入
```

### 校對狀態

889 條**全部**逐條檢查過，不是抽樣：

- 結構檢查（`tools/check_lexicon.py`）：**889 條 0 問題**
- 文法／字義／中譯校對：切成 23 批各 40 條逐條檢查，
  共提出 53 項，**48 條**進入 `tools/fixes.json` 實際修正

修正內容包括原書本身的錯誤，例如：

| 條目 | 原書 | 修正 |
|---|---|---|
| 3-041 | She always **get** good grades. | She always **gets** good grades. |
| 2-085 | **Whe**'s your Chinese teacher? | **Who**'s your Chinese teacher? |
| 3-017 | with **a chalk** | **a piece of chalk** |
| 5-184 | practices the violin **everyday** | **every day** |
| 6-130 | is hard-working person | is **a** hard-working person |
| 2-045 | his **studentcheated** on the test | his student **cheated** |
| 5-180 | on **Tues- day** night | on **Tuesday** night |
| 4-021 | chess＝棋子 | chess＝**西洋棋** |
| 5-013 | **烘培** | **烘焙** |

其中有 2 筆屬於譯法偏好而非錯誤（`2-065`、`2-077`），

- **需要打字的字串不含非 ASCII**（沒有鍵盤打不出來的字），

## 已知限制

- CMUdict 查不到縮寫與人名（MRT、Lucy、Jo 等），這些詞的音標會被略過，
  所以整句音標有時候比句子短一點。已知漏網的專有名詞列在
  `tools/check_ipa.py` 的 `NAMES` 白名單裡，加新名字要順手加進去。
- CMUdict 有少數條目的首選讀音不常見（`nobody` 的第一條是
  `N OW1 B AA2 D IY2`，實際唸的是第二條 /ˈnoʊbədi/），
  這種要人工在 `tools/fetch_ipa.py` 另外覆寫。
- 音標是**美式**（CMUdict），跟台灣部分教材採用的英式標法會有出入
  （例如 `schedule`）。
- 語音朗讀使用瀏覽器的 `speechSynthesis`，需要系統有英文語音；
  沒有英文語音時頂欄會顯示提示，其他功能仍正常。
- 詞組步驟已經 100% 補滿，以後新增單字時若忘了配對照表，
  `npm run build` 會直接失敗並把缺口寫進 `tools/need_phrase.txt`。
